Privacy policy

This is the privacy policy linked from the Google sign-in screen for Scoped Drive.

Scoped Drive is a gateway in front of Google Drive. Drive’s API has no fine-grained control for sharing only selected files and folders with an app, so this server asks for broad Drive access and then enforces the list you tick yourself.

This deployment is run by the person who set it up. The only Google account that can open the dashboard is the owner account configured for it.

Google data we use

Sign-in requests these Google permissions, and no others:

  • openid and email, to read the account’s email address and whether Google has verified it. We use that only to check that the account is the configured owner or, if you connect a separate bot account, that bot account. We do not ask for your name, contacts, or other profile information.
  • https://www.googleapis.com/auth/drive, full access to Drive. Drive does not offer a permission for “only these files and folders.” The narrower drive.file scope only covers files this app created or that you pick one at a time, so it cannot keep an existing folder available to the assistant. After you approve the broad scope, this server applies its own limit: an assistant can only list, read, or change items you have ticked, or items inside a folder you have ticked.

What an assistant can do depends on the role of the connection you gave it. That can include search, reading text, creating files and folders, editing, renaming, and moving an item to Drive’s trash. There is no tool here to permanently delete a file, to change who a file is shared with, or to move a file between folders.

How a call reaches Drive

In the usual setup, a second Google account (the bot) is the identity the assistant’s tools use. Ticking an item shares that item with the bot in Drive, using your own sign-in. The bot cannot see the rest of your Drive, and this server still checks the list before each call.

You can instead run in same-account mode. The tools then use your own sign-in, and the only limit is this server’s list. The dashboard shows which mode is active.

File contents are read from Drive only to answer a tool call, then returned to the assistant. This server does not keep a copy of file contents.

What we store

We store:

  • Your Google refresh token, encrypted, so the server can keep calling Drive after you close the browser. It lives in Redis (Upstash).
  • The allowlist: the Drive file and folder ids you ticked.
  • Access requests, kept for 7 days: a request id, the file id, a short description, the tool name, the connection name, your decision, and the file name only when the bot can already see that file.
  • An activity log of the last 500 events: time, tool name, allow or deny, and ids. File contents, file names, and search text are not written there. The same lines go to the host’s logs.
  • A signed session cookie in your browser for the dashboard, lasting about 8 hours. It does not contain your files.
  • If an assistant connects with OAuth: the name it registered and the tokens issued for that connection, so you can disconnect it.

Who receives it

Google holds your files and handles sign-in. The assistant you connect (for example Grok) receives the tool results for items you allowed, including file text when it reads a file. What that assistant stores is covered by its own policy.

The app runs on Vercel. The encrypted token, allowlist, requests, and activity log are stored in Upstash Redis. Those providers keep that data so the gateway can run. They are not given your Drive as a product of their own.

Limited use of Google user data

Scoped Drive’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Google user data is used only to provide this gateway, which is the feature shown on the home page: check the list you set, call Drive for the items you allowed, and return the result to the assistant you connected. That assistant is the only destination for file contents. Sending a result there is the feature you turned on by connecting it and ticking those items.

We do not sell Google user data. We do not use it for advertising, credit, lending, or to train a model. We do not pass it to anyone other than that assistant, except to keep the service secure, to comply with the law, or as part of a transfer of this deployment after you agree. This server has no page that shows file contents to a person, and the activity log does not contain them. People do not read those contents unless you ask, or it is required for security or by law.

Your choices

Sign out, untick items, disconnect the bot or the assistant, or remove this app’s access in your Google Account settings. Removing it stops this server from using the stored Google sign-in. Clearing this deployment’s Redis data removes the stored token, allowlist, and requests.

Questions about a deployment go to the person who runs it, the Google account configured as its owner. See also the terms.
